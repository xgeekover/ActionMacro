# tools — 실기기 점검 스크립트

`tests/` 의 자동 테스트는 화면 없는 Qt(offscreen)에서 pynput·mss 를 가짜로 바꿔 돈다. 그래서 **실제 데스크톱에서만 생기는 문제**는 잡지 못한다.
2026-10-24 처음 실기기에서 돌렸을 때, 테스트 727개가 모두 통과한 상태에서 앱이 **클릭·키 단계 시작 순간**과 **긴급 정지 리스너가 켜지는 순간** 강제 종료됐다
(pynput 이 macOS 키보드 입력 소스 API 를 메인 스레드 밖에서 불러 SIGTRAP). 입력 · 단축키 · 좌표 피커 · 엔진의 스레드 구조를 고친 뒤에는 아래 점검을 돌린다.

> ⚠️ 두 스크립트 모두 **실제 마우스·키보드를 움직인다.** 도는 동안 손을 뗀다.

## 필요한 권한 (점검을 실행하는 터미널 앱에)

시스템 설정 → 개인정보 보호 및 보안:
- **손쉬운 사용** — 마우스·키 입력을 보낸다
- **입력 모니터링** — 전역 단축키 리스너와 키 이벤트 기록

화면 기록 권한은 필요 없다(화면을 캡처하지 않는다).

## 1. 자동 점검 — `device_check_macos.py` (약 20초)

```bash
.venv/bin/python tools/device_check_macos.py                 # 전체 점검
.venv/bin/python tools/device_check_macos.py --stop-key-trials 10   # 키 누르는 도중 정지만 10번 반복
```

| 점검 | 통과 기준 |
|---|---|
| 클릭 정밀도 — 모니터마다 10회 (왼쪽·위쪽 모니터의 음수 좌표 포함) | 오차 ≤ 1px |
| 더블클릭 (clicks=2) | Qt 가 더블클릭으로 받음 |
| 긴급 정지 — 연속 클릭 · 3초 클릭 누르기 · 3초 키 누르기 도중 | 50ms 뒤 새 입력 0건, 100ms 안에 눌린 것 해제 |
| **실제 메인 창** — 시작 버튼 → 클릭 (전역 단축키 리스너 켜짐) | 충돌 없음, 정확한 위치 클릭, 실행 중 리스너 살아 있음 |
| 조합키 — `shift+a`, `cmd_or_ctrl+a`, down/up, 예전 파일의 `modifiers` | OS 가 받은 키 이벤트 순서(앞 키 누른 채 → 마지막 키 → 역순 해제) |
| 좌표 피커 — 모니터마다 | 찍은 좌표 = 클릭한 좌표 |
| 전역 단축키 리스너 | 이벤트 탭 스레드가 살아 있음 |

결과는 화면에 `[PASS]/[FAIL]/[SKIP]` 으로 찍히고 `device_check_report.json` 에 단계마다 저장된다. 종료 코드: 0 통과, 1 실패 있음, 3 감시 시간 초과.
충돌하면 133(SIGTRAP — `~/Library/Logs/DiagnosticReports/python3*.ips` 확인) 또는 139(SIGSEGV — `<report>.crash.txt`).

### 안전 장치
- 클릭 직전마다 **그 좌표의 맨 위 창이 점검 프로세스의 창인지** 확인하고, 아니면 그 단계를 건너뛴다(SKIP).
- 키 입력은 **점검 창이 맨 앞 앱이고 입력란에 포커스가 있을 때만** 보낸다. 키 단계마다 다시 확인한다.
- 키 이벤트는 수신 전용 이벤트 탭으로 기록하되 **점검 프로세스가 보낸 이벤트만** 남긴다. 사용자가 직접 치는 키는 기록하지 않는다.
- 120초(`--timeout`)가 넘으면 눌린 입력을 모두 풀고 스스로 끝난다. 끝나면 커서를 원래 자리로 돌린다.

## 2. 직접 누르는 긴급 정지 — `device_check_hotkeys_macos.py` (대화형)

전역 단축키 리스너는 프로그램이 보낸 키를 일부러 무시하므로, "사람이 Esc 를 누르면 멈춘다"는 사람이 눌러야만 확인된다.

```bash
.venv/bin/python tools/device_check_hotkeys_macos.py
```

메인 창이 뜨고 **대기만 반복하는 무한 매크로**(입력을 보내지 않는다)가 돈다. 안내가 나오면:
1. **Esc** 를 한 번 — 어느 창에 포커스가 있든 상관없다.
2. 약 1.5초 뒤 매크로가 다시 시작되면 **Ctrl+Shift+S** 를 한 번.

기록하는 것은 이 두 키를 누른 시각뿐이다. 종료 코드: 0 둘 다 멈춤, 1 기대와 다름, 2 시간 초과(기본 240초).

## 알아 둘 점 (2026-10-24 실측, macOS 26.6 · 외장 1배 모니터 2대)

- **한글 입력기(두벌식)** 상태에서는 매크로가 보낸 `a` 키가 입력란에 `ㅁ` 으로 찍힌다 — 사람이 눌러도 같다. 키 이벤트 자체는 정확하다(점검은 이벤트로 판정한다). 게임에 따라 한글 상태에서 키가 먹지 않을 수 있다.
- 엔진은 실행이 끝날 때마다 **누르지 않은 ctrl/alt/shift/cmd 까지 무조건 놓는다**(이벤트 열 끝의 4개). 점검은 이것을 떼어 내고 판정한다.
- 독(Dock)과 알림 센터는 화면 전체를 덮는 투명 창이라 맨 위 창 판정에서 뺀다. 대신 클릭 목표는 화면 아래 200px 위에 둔다.
- 앞서 충돌한 프로세스의 **"Python이 예기치 않게 종료되었습니다" 경고창**이 남아 있으면 그 자리 클릭은 SKIP 된다. 닫고 다시 돌린다.
- 실행 직후 시스템 키 상태가 몇 ms 동안 '눌림'으로 읽힐 수 있다 — 정지 판정은 400ms 시점의 상태로 한다.
- 엔진은 목표로 커서를 옮긴 뒤 **그 순간의 커서 위치에서** 버튼을 누른다. 점검 중 마우스·트랙패드가 살짝 움직이면 받은 좌표가 소수점만큼 어긋난다
  (한 번은 0.9px, 커서는 1~3px 밀림 — 기준 1px 안). 크게 움직이면 클릭이 빗나갈 수 있으니 손을 뗀다.

| 기준선 결과 | 값 |
|---|---|
| 클릭 오차 (주 모니터 · 왼쪽 보조 모니터 음수 좌표) | 0px (손을 뗐을 때) |
| 긴급 정지 — 실행 스레드 종료 / 버튼·키 해제 | 1.5~7ms |
| 직접 누른 Esc / Ctrl+Shift+S | 24ms / 1ms 미만 |

## 아직 없는 것
- **이미지 인식(실제 화면 캡처)** 점검 — 터미널 앱에 화면 기록 권한이 필요하다.
- **레티나 화면 · Windows** — 이 스크립트는 macOS 전용이고, 위 기준선은 1배 모니터에서 쟀다.
